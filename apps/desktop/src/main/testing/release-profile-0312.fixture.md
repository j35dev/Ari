## Checks

`src/main/release-profile-upgrade.test.ts` cold-loads the frozen bundle through current stores. It verifies saved defaults/tombstone identity, transcript and queue preservation, staged bytes, scheduler preservation, fresh-service receipt reuse/refusal without repeat effects, and runtime recovery with a single scripted adapter.

One captured v5 index is deliberately made stale (`journalBytes: 0`, stale cached title and omitted optional lead/creator metadata), following the crash/cache boundary documented in SessionStore. Listing repairs it from the unchanged journal, preserving lead identity. A settings variant uses the known retired `alt-right` shortcut and absent delegation marker to exercise existing one-time migrations. Another variant uses the newer general default as the old Aria shortcut.

Candidate source at preliminary head `652b85b68a235c8af7834299db76113c77bb2b28` was inspected read-only. It preserves legacy `speech.shortcut` as Aria and adds `dictationShortcut` / `duckAudio`. When the checked-out desktop package version differs from the fixture's 0.3.12 source version, assertions require persisted independent defaults and the `ctrl+alt+shift+d` collision fallback. A missing candidate field fails rather than skipping the check. **These candidate-only branches are not exercised by v0.3.12 baseline execution.** Run against the exact reviewed candidate to establish them.

`src/renderer/src/features/composer/release-profile-upgrade.test.ts` hydrates frozen jsdom storage using actual draft modules. Preparing receipts become unsent; pending receipts become uncertain. Text, metadata, staged IDs and review notes survive; File objects/live pending promises do not return. A subsequent persistence write retains the original session's work. Nothing submits itself.

Run from the desktop workspace through the repository's normal Node/jsdom projects:

## Startup boundaries and limits

Actual startup source routes settings load through `rpc.ts` controlReady, constructs ProjectStore with its Aria built-in in `store.ts`, and reads/repairs session indexes on listing/replay. `startAgentRuntime` starts DelegationSupervisor; its recovery interrupts stale delegated turns without resubmitting an unconfirmed turn. After controlReady, `rpc.ts` calls Engine.drainHeld. The test invokes these **existing runtime primitives explicitly**, with event-driven bounded waits; it does not boot the complete RPC/Electron host.

Store loading is not a packaged installer upgrade. Native profile-directory selection, Chromium storage retention by an installer, OS credential encryption, native shortcut registration, microphone/audio routing, provider reconnection, worktree/Git ownership cleanup and packaged startup remain unverified. The fixture represents the current 0.3.12 registry envelope, not all older bare-array project registries. It covers existing 0.3.12 worker recovery receipts; new candidate project-creation partial receipts did not exist in that version and are not invented in this fixture.

No production source or schema changes are included. Final-candidate execution and parent review are still required before release.
