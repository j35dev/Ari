Reimagining the “New session” project picker

Today, clicking New session reuses the sidebar’s right-click menu — a flat, 184 px list. Each project appears twice (regular + “Lead session in…”), names truncate, Add project… competes with projects, and there is no way to search when you have many. Below: the current design for reference, then three concepts. All mockups are live — type into the search, hover rows, use the keyboard.

Reference

What ships today

Problems to kill:

  • Duplicate rows — every project is listed twice (session + lead session); the list grows 2× per project.
  • No identity — bare names in a 184 px menu; nothing shows the folder, activity or size.
  • No search — with 8+ projects you scan the whole list by eye.
  • Mixed intent — “Add project…” sits inside the same namespace as projects.
  • Wrong vocabulary — it’s the Context menucomponent (built for right-click on a sidebar row), not a launcher.

Concept A · Recommended

The Session Launcher — search-first, one row per project, lead on hover

A centered launcher (like a mini command palette but dedicated): type-to-filter, recents first, one row per project, and the lead-session option appears as a hover chip or Alt+↵ — instead of doubling the list. rich rows show folder paths and live metadata so you’re choosing by context, not just name.

  • Rows lead with memory — “2h ago” and session counts turn the chooser into “where was I?”, which is usually the actual question when this opens.
  • 1–9 number keys jump straight to a row; Enter opens first result (already focused).
  • Lead session lives per-row as a chip on hover + Alt-Enter, deduplicating the list entirely.
  • Footer carries escape hatches — Add project + resurrect-last-session, out of the project namespace.

Concept B

Palette mode — minimal, command-palette faithful, fastest by keyboard

Tighter palette variant that leans on the same muscle memory as the command palette: nothing but a field, ranked rows and a thin footer. Projects are flat (no sections), paths hidden until hover — the tersest option, closest in spirit to VS Code/Arc/Raycast.

  • Minimal chrome — no section labels, no visible metadata; the smallest, most keyboard-native version.
  • Lead also compact — typed as a hint in the result meta rather than a separate row; picking a project with an active Alt modifier creates the lead session.
  • Weakest at browsing — great when you know your project, poorer at “what have I been doing?”.

Concept C

Anchored rail sheet — keeps locality, adds richness

Same mental model as today (appears right under the New-session button), but a proper launcher card instead of the context menu — richer rows, search, and still tight to where you clicked. Least disruptive upgrade if you want the spatial habit preserved.

  • Locality — anchored to the trigger; extra movement mapping is near-zero.
  • Escalation of clarity — same row anatomy as Concept A, but compact and the list is capped at ~5 rows with scroll after.
  • Tradeoff — less room for metadata than the centered launcher; paths shorten to the segment on hover.
