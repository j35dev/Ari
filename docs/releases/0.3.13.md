# Ari 0.3.13 candidate

These are candidate notes. Publication is gated on combined platform, packaged runtime and upgrade checks.

## Startup and navigation

- Selecting a project in New Session creates and selects the session reliably by pointer, while retaining keyboard startup.
- Returning to a known Aria chat does not wait for provider discovery. Late discovery cannot replace a newer chat selection, and failed discovery can be retried.
- Aria-launched sessions retain the project's selected provider, model, reasoning and permission choices. Unavailable saved choices remain intact with an actionable availability reason.
- Background ACP discovery uses isolated probes without configured MCP servers.

## Speech input

- Long recording stays active until stopped, with separate recording and inference budgets.
- Settings exposes separate Aria dictation and general dictation shortcuts. Existing saved shortcuts retain their Aria intent.
- Composer dictation preserves the draft and insertion position without submitting it. General Windows dictation targets the captured external text field and preserves clipboard contents.
- Both global shortcuts share readiness-gated audio ducking and restoration. Capture leases and stale-callback guards protect the intended destination.

## Aria coordination and recovery

- Queued assignment reads expose bounded text, origin, held state and count. Busy-prompt receipts identify future-turn delivery, and whole-turn reads retain the existing size cap.
- Model-switch receipts identify whether a change is ready or takes effect after the current turn. Explicit current-Aria self-switch requests retain catalog, scope and permission checks.
- Completion outcomes and question/report ownership use the effective live owner, including deleted or archived old Aria topics. Uncertain steering replies remain inspectable rather than being treated as safely retryable.
- Partial project creation and uncertain worker launches preserve the recorded folder, phase and worker/workspace identity on same-key retry. Registry writes remain ordered and unavailable directories are reported accurately.

## Upgrade and limits

The intended upgrade baseline is 0.3.12. Existing project defaults, transcripts, queues, drafts and shortcuts must pass disposable-profile and packaged-upgrade gates before publication. Speech models remain optional downloads; no TTS engine or voice model is included.

Project folder creation and its first durable progress write are not atomic. A process exit between them can leave an unrecorded folder. Native microphone/focus/audio behavior and cross-platform packaged runtime checks remain release gates; unit tests alone do not establish them. Targeted rename/pin/archive and sidebar project actions are deferred.
